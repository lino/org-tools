* Introduction and Goals

** Requirements Overview

org-tools is a unified CLI for org-mode files written in Rust. It provides
linting, formatting, querying, updating, clocking, archiving, and exporting —
all without requiring Emacs.

Key requirements:

- *Standalone*: no Emacs dependency — runs as a single binary
- *Fast*: process large org-mode collections in sub-second time
- *Correct*: rule behaviour matches the org-mode specification and Emacs
  org-lint where feasible
- *Safe*: never corrupt user files; protected regions (source blocks, example
  blocks, etc.) are never modified by format rules
- *Configurable*: rules can be enabled/disabled via =.org-tools.toml=; defaults
  match Emacs org-mode behaviour
- *Composable*: commands produce output in formats suitable for piping
  (=org query search 'todo:TODO' --format locator | org update set-state NEXT --stdin=)

** Quality Goals

| Priority | Quality Goal  | Description                                                     |
|----------+---------------+-----------------------------------------------------------------|
| P1       | Correctness   | Rules match org-mode spec and Emacs behaviour                   |
| P2       | Safety        | Never modify content inside protected regions                   |
| P3       | Performance   | Sub-second for typical org-mode collections (hundreds of files) |
| P4       | Extensibility | Adding a new rule requires only a struct + trait impl + tests   |
| P5       | Composability | Commands pipe together via locators and JSON envelopes          |

org-tools reads =.org= files from the filesystem, applies format/lint/query/mutation
operations, and outputs results to stdout. Commands compose via locator strings
and JSON envelopes on stdin/stdout.

** Technical Context

org-tools is a pure command-line tool. Its only I/O is:

- *Input*: =.org= files from the local filesystem, =.org-tools.toml= configuration,
  environment overrides (e.g. =BABELSBERG_ID_NAMESPACE=, =ORG_TAG_COLUMN=), and stdin
- *Output*: diagnostics, query results, =MutationResult= JSON envelopes, locators,
  and formatted or exported files to stdout/stderr

No network access, no database, no external APIs.

* Solution Strategy

The project is structured as a *Cargo workspace* with a shared library and a
modular umbrella binary:

- =org-tools-core=: all parsing, format/lint rules, =OrgDocument= heading and
  =org-roam= v2 file-node model, =OrgLocator= resolution, property/tag/ID/planning
  mutations, =MabuseCache= SQLite WAL + FTS5 indexing, archiving, =org-edna=
  dependencies, and =#+TBLFM:= evaluation
- =org=: unified CLI and =stdio= MCP server dispatching modular subcommands
  (=fmt=, =query=, =roam=, =show=, =update=, =clock=, =archive=, =export=,
  =cache=, =mcp=, =schema=)

** Lint & Format Strategy

Line-based text processing with span-based fixes:

1. Read file into =SourceFile= (indexes line starts for O(log n) lookups)
2. Run *format rules* → collect =Fix= structs (byte span + replacement)
3. Deduplicate and apply fixes in a single pass
4. Run *lint rules* on formatted result → collect =Diagnostic= structs
5. Output in requested format

** Query & Mutation Strategy

1. Parse =.org= files into =OrgDocument= trees (including top-of-file =org-roam=
   v2 =:PROPERTIES:= drawers, =#+PROPERTY: KEY+= continuations, and plain-list
   =ChecklistItem= vectors)
2. Resolve =OrgLocator= targets or evaluate recursive-descent =Predicate= ASTs
3. Apply lint-clean mutations (F005-aligned drawers, F007 column-77 tags,
   Stempelamt RFC 9562 UUIDv5 + =:ID_SEED:= minting) and emit uniform
   =MutationResult= JSON envelopes with execution =telemetry=

** Level 4: Rule Architecture

Every rule is a struct implementing =FormatRule= or =LintRule=:

#+begin_src rust
pub trait FormatRule: Send + Sync {
    fn id(&self) -> &'static str;          // e.g. "F001"
    fn name(&self) -> &'static str;        // e.g. "trailing-whitespace"
    fn description(&self) -> &'static str;
    fn format(&self, ctx: &FormatContext) -> Vec<Fix>;
}

pub trait LintRule: Send + Sync {
    fn id(&self) -> &'static str;          // e.g. "W001"
    fn name(&self) -> &'static str;        // e.g. "heading-level-gap"
    fn description(&self) -> &'static str;
    fn check(&self, ctx: &LintContext) -> Vec<Diagnostic>;
}
#+end_src

Rules are independent — no rule depends on another rule's output.

* Deployment View

org-tools is distributed as a single statically-linked binary with zero runtime
dependencies via **GoReleaser OSS v2** (=.goreleaser.yaml= and
=.github/workflows/release.yml=):

- *Multi-OS release archives*: =aarch64= and =x86_64= builds for macOS
  (Darwin), static =musl= Linux (=cargo-zigbuild=), and Windows MSVC
  (=cargo-xwin=), bundling =bash=, =zsh=, and =fish= shell completions and
  verified by =scripts/verify-release-packages.sh=
- *Linux system packages*: =.deb= and =.rpm= packages built via GoReleaser nFPM
- *macOS Homebrew Cask*: published to =lino/homebrew-tap= (=brew install --cask lino/tap/org-tools=)
- *Source & Cargo*: =mise run install= or optional =crates.io= publishing
  (=org-tools-core= and =org-tools=) when =CARGO_REGISTRY_TOKEN= is configured

* Cross-cutting Concepts

** Protected Regions

Format rules must never modify content inside org-mode blocks where the
content is literal text (source, example, export, quote, verse, center,
comment blocks). The =regions.rs= module scans for =#+BEGIN_= / =#+END_=
pairs and returns line ranges. Format rules call =is_protected()= to skip
these lines.

** Fix Application

Fixes are span-based: each =Fix= specifies a byte range and its replacement.
The formatter applies fixes in a single left-to-right pass, which requires
fixes to be sorted by start position and non-overlapping. The runner handles
deduplication by keeping the first fix when spans overlap.

** Configuration Hierarchy

org-tools searches for =.org-tools.toml= starting from the current directory and
walking up to the filesystem root. The first file found wins. This allows
per-project and per-directory configuration.

** OrgLocator — Universal Entry Addressing

Every heading — as well as a level-0 =org-roam= v2 file node carrying a
top-of-file =:ID:= drawer — can be addressed by an =OrgLocator= string. When an
entry has an =:ID:= property, the locator uses that (surviving moves across
files). Otherwise, it falls back to =CUSTOM_ID=, outline path, or line number.

** Rule Independence

Rules are fully independent — no rule reads another rule's output. This
makes the system easy to reason about, test, and extend. Each rule is a
self-contained module with its own tests.

* Risks and Technical Debt

| Risk / Debt                   | Mitigation                                                       |
|-------------------------------+------------------------------------------------------------------|
| Line-based parsing has limits | Sufficient for ~35 of ~58 org-lint checks + OrgDocument headings |
| Table alignment is left-only  | Track as known divergence from Emacs; future fix                 |
| Coarse filesystem mtime ticks | Explicit =invalidate_paths= clears cached fingerprints on writes |
| No parallel file processing   | Single-threaded + warm SQLite WAL cache is sub-50 ms at scale    |

* Glossary

| Term             | Definition                                                    |
|------------------+---------------------------------------------------------------|
| Format rule      | A rule that produces =Fix= values to auto-correct formatting  |
| Lint rule        | A rule that produces =Diagnostic= values (report-only)        |
| Protected region | A block (src, example, etc.) whose content must not be        |
|                  | modified by format rules                                      |
| Fix              | A byte-span replacement: replace bytes [start, end) with      |
|                  | new text                                                      |
| Diagnostic       | A reported issue: file, line, column, severity, rule, message |
| Runner           | Orchestrates rule execution and fix application               |
| SourceFile       | In-memory representation of an =.org= file with line index    |
| OrgDocument      | Heading tree and =org-roam= v2 file-node metadata model       |
| OrgEntry         | A heading entry with properties, planning, clocks, checklist  |
| OrgLocator       | Universal address for a heading or file node                  |
| MutationResult   | Uniform JSON envelope with per-entry details and =telemetry=  |
| Predicate        | A query condition evaluated against an OrgEntry               |
